Overview

Shorty is a lightweight content manager with two table formats:

  • ShortyHTML: HTML tables stored as minimal markup under -ShortyTables/<username>/.
  • ShortyJSON: JSON arrays of row objects stored under -ShortyTables/<username>/.

Which Format Should I Use?

For plain text snippets, both formats work. Choose based on what happens after editing:

  • Prefer ShortyJSON when you need automation, scripting, data transforms, imports/exports, or API/tool integration.
  • Prefer ShortyHTML when you need presentation-oriented content that is ready for browser/web rendering.
  • Rule of thumb: JSON for data workflows, HTML for display workflows.

Key Concepts

  • Storage: Files are stored per user in -ShortyTables/<username>/.
  • Separation of concerns: Shorty keeps stored HTML lean and applies UI styling at render time.
  • Rendering: The app applies the ShortyTable (render-time) CSS class to tables so they display consistently. Stored files remain unstyled so they are portable and editable by other tools.
  • Actions: When displayed in the UI, an extra Actions column is appended with Copy / Edit / Delete buttons — this column is runtime-only and not saved to disk.

Using the UI

  1. Open ShortyHTML from the sidebar selector. Newly created items appear in the selector and open immediately.
  2. To create a new ShortyHTML file, click New ShortyHTML, enter a filename (no extension) and the file will be created under -ShortyTables/ with a one-row scaffold so you can start editing.
  3. To create a new ShortyJSON file, use the New JSON button in the ShortyJSON view. A scaffolded JSON file with one empty row is created so it renders immediately.
  4. Edit cells directly (most cells are contenteditable) then click the row's Save button to persist changes. The app strips runtime-only markup and inline styles before saving.
  5. Use the Copy button to copy the left-hand cell of a row to the clipboard. Use Delete to remove a row (requires confirmation).

Rich Content in ShortyHTML (Images, Video, Markdown)

Phase 1 (implemented): ShortyHTML now supports per-cell markdown mode with safe rendering. Markdown source is stored as text and rendered in the UI preview, while preserving a minimal saved HTML structure.

What is still next:

  1. Add rich HTML mode as a separate opt-in cell mode.
  2. Extend allowlist sanitization for media: keep safe tags like strong, em, a, ul, ol, li, p, br, img, video, source; keep only safe attributes like href, src, alt, title, controls, width, height.
  3. Support uploads for media: save user media files under a user-scoped folder and store relative URLs in the table cells.
  4. Keep JSON as plain data: rich-content features should stay opt-in for ShortyHTML so ShortyJSON remains automation-friendly.

Developer Notes

Location of important files:

  • Templates: App/templates/ (see core/shortytable.html and core/shortyjson.html).
  • Static CSS: App/static/Shorty-style.css contains presentation rules applied to the rendered tables.
  • Saved data: -ShortyTables/<username>/ contains user-created files (.html & .json).
  • Server endpoints: /create_table, /create_json, /save_html, and /save_json in App/core/views.py.
  • List endpoints: /list_html for ShortyHTML files and /list_json for ShortyJSON files.

Styling

The app intentionally keeps saved files unstyled. Presentation is handled at render time. If you need to change layout or row heights, update App/static/Shorty-style.css (selectors target the runtime table class and cell divs).

Local Development

  1. Create and activate a virtualenv: python -m venv .venv then source .venv/bin/activate.
  2. Install requirements: pip install -r requirements.txt.
  3. Run the Flask app: flask run or use the existing manage.py entrypoint.

Notes & Best Practices

  • Saved HTML is minimal. Avoid adding inline styles to stored files — use the app stylesheet instead.
  • When altering the runtime class name or behavior, update both CSS and server-side code that expects the class (see App/core/views.py where runtime Actions are appended).
  • If rich content is enabled later, keep server-side sanitization strict and explicit to reduce XSS risk.
